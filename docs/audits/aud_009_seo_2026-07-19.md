> Audyt dedykowany widoczności w wyszukiwarkach. Uzupełnia audyty `aud_007`/`aud_008`
> o pełną analizę techniczną SEO, treściową i strukturalną — wraz z gotowymi do wdrożenia
> poprawkami (fragmenty kodu w §7). Stan repo: commit `e632c84`.

---

## 1. Podsumowanie

**Ocena SEO: 3/5 — solidne fundamenty, brak warstwy „wykończeniowej".**

Strona ma to, co najtrudniejsze: pełny prerendering (cała treść w HTML-u, bez zależności
od JS), poprawną semantykę nagłówków, meta tagi na każdej trasie, JSON-LD i dobre
Core Web Vitals w warstwie bundle'a. Brakuje natomiast elementów, które są tanie we
wdrożeniu, a bez których Google nie ma pełnego obrazu strony: **sitemap, robots.txt,
canonical, dedykowany obraz OG, dane strukturalne FAQ** — oraz warstwy słów kluczowych:
obecne tytuły i nagłówki są emocjonalne, ale **nie zawierają ani jednej frazy, którą
wpisuje potencjalny klient** („kamerzysta na wesele", „film ślubny", nazwa miasta).

Trzy najważniejsze wnioski:

1. **Ryzyko krytyczne**: bez ustawionego `SITE_URL` wszystkie canonical/OG wskazują
   `https://example.com` — to aktywnie szkodzi indeksacji, zamiast być neutralne.
2. **Najtańszy duży zysk**: `sitemap.ts`, `robots.ts`, canonical, FAQPage JSON-LD
   i poprawne tytuły — łącznie ~2–3 godziny pracy, pokrywają 80% braków technicznych.
3. **Największa dźwignia długoterminowa**: lokalność (miasto/region w tytułach, treści
   i danych strukturalnych) oraz docelowo osobne podstrony usług — bez tego strona nie
   zaistnieje na frazy transakcyjne typu „kamerzysta na wesele [miasto]".

## 3. Braki techniczne (szybkie do naprawy)

### 3.1. Brak `sitemap.xml` i `robots.txt` 🔴

W `app/` nie ma `sitemap.ts` ani `robots.ts`. Skutki: Google odkrywa trasy tylko przez
linki, brak sygnału priorytetów i dat modyfikacji; brak wskazania sitemapy w robots.
Przy 3 trasach to 15 minut pracy — gotowy kod w §7.1–7.2.

### 3.2. Brak canonical 🔴

`metadataBase` jest ustawione, ale Next.js **nie emituje** `<link rel="canonical">`
automatycznie — wymaga `alternates.canonical`. Bez canonical każda wariacja URL-a
(`?fbclid=…`, `/#about` w indeksie) może rozmywać sygnały. Poprawka: §7.3.

Powiązane ryzyko: fallback `SITE_URL = 'https://example.com'` oznacza, że **przy braku
zmiennej na produkcji canonical i OG wskażą cudzą domenę** — gorsze niż brak canonical.
Rekomendacja: walidacja env przy buildzie (fail-fast) — §7.6.

### 3.3. Obraz OG / favicon 🔴

`Hero_v4.png` (1,4 MB, proporcje portretowe) służy jako favicon, apple-icon, obraz OG
i Twitter Card. Problemy:

- Facebook/LinkedIn oczekują ~1200×630 (1.91:1); portretowy PNG będzie ucięty losowo.
- Część serwisów odrzuca obrazy > 1 MB → podgląd linku bez grafiki.
- Favicon 1,4 MB pobierany przez każdą kartę przeglądarki.

Poprawka: pliki konwencji App Routera — `app/icon.png` (48–512 px), `app/apple-icon.png`
(180×180), `app/opengraph-image.jpg` (1200×630, < 300 kB). Next sam wygeneruje meta tagi;
usunie się wtedy ręczne `icons`/`images` z layoutu.

### 3.4. Dane strukturalne — wykorzystane w ~20% 🟠

Obecny JSON-LD to minimalny `ProfessionalService`. Brakuje pól, które strona **już ma
w treści**, oraz dwóch dodatkowych typów:

| Schemat | Stan | Źródło danych już istnieje |
| --- | --- | --- |
| `ProfessionalService.sameAs` | ❌ | 5 profili social w `site-content.ts` |
| `ProfessionalService.telephone` / `email` | ❌ | dane kontaktowe (po uzupełnieniu env) |
| `ProfessionalService.image` / `logo` | ❌ | grafika OG |
| `FAQPage` (9 pytań) | ❌ | pełna sekcja FAQ w `site-content.ts` — **największa okazja**: kwalifikuje do rich results w SERP |
| `VideoObject` dla filmów promo | ❌ | tytuły + ID YouTube w `site-content.ts` |
| `BreadcrumbList` na podstronach | ❌ | 3 trasy (niski priorytet przy płaskiej strukturze) |

Gotowy kod FAQPage i rozszerzonego ProfessionalService: §7.4–7.5.

### 3.5. Tytuły stron — trzy konkretne błędy 🟠

| Trasa | Obecny `<title>` (po szablonie) | Problem |
| --- | --- | --- |
| `/` | `Portfolio Fotograficzno-Wideo \| Autor`* | brak frazy usługowej i lokalizacji; „Portfolio" to słowo, którego klient nie wpisuje |
| `/oferta` | `Oferta — Maleszyk Media \| Autor`* | **podwójny branding** — tytuł z `site-content` zawiera już nazwę marki, a szablon dokleja drugą |
| `/contact` | `O mnie \| Autor`* | **tytuł nie odpowiada trasie** — URL mówi „kontakt", title mówi „o mnie"; miesza intencje i osłabia oba tematy |

\* `Autor` = fallback `AUTHOR_NAME`; przy poprawnym env będzie to imię i nazwisko / marka.

Rekomendowane wzorce (do dopasowania z właścicielem):

- `/` → `Kamerzysta i fotograf — śluby, eventy, dron | Maleszyk.Media`
- `/oferta` → `Oferta — film ślubny, montaż, wideo promocyjne` (szablon doklei markę)
- `/contact` → `Kontakt i o mnie` lub rozdzielenie tras (§5.2)

### 3.6. Drobne

- `metadata.robots` można rozszerzyć o `googleBot: { 'max-image-preview': 'large' }` —
  większe miniatury w Discover/SERP.
- Brak `twitter:site`/`twitter:creator` (jeśli istnieje konto X — opcjonalne).
- OG bez per-page obrazów — po dodaniu `opengraph-image` w `app/` problem znika dla
  wszystkich tras naraz (dziedziczenie).

## 4. Warstwa treści i słów kluczowych

### 4.1. Brak fraz usługowych w elementach o najwyższej wadze 🟠

Nagłówki są brandowo-emocjonalne: h1 na `/` = „Zatrzymuję czas Zapisuję emocje",
h1 na `/oferta` = „Oferta", h2 sekcji = „O mnie", „Proces", „FAQ". Żaden nagłówek na
stronie nie zawiera fraz typu *film ślubny, kamerzysta, wideofilmowanie, fotograf
eventowy, dron*. Wyszukiwarka rozumie stronę głównie z meta description i treści FAQ.

Rekomendacje (bez psucia stylu strony):

- h1 `sr-only` na stronie głównej jest **idealnym miejscem** na wersję z frazami —
  jest niewidoczny wizualnie: np. „Kamerzysta i fotograf — filmy ślubne, eventy,
  materiały promocyjne i ujęcia z drona". Widoczny napis „Zatrzymuję czas…" zostaje
  bez zmian (jest w `<p>`).
- Podtytuły sekcji (widoczne `<p>`) mogą naturalnie przemycać frazy („…od filmu
  ślubnego po materiały promocyjne dla marek").
- `/oferta`: h1 „Oferta" → „Oferta — filmy ślubne, montaż, wideo promocyjne".

### 4.2. Zero sygnałów lokalnych 🔴 (dla biznesu usługowego)

W całej treści, metadanych i JSON-LD nie pada **żadne miasto ani region** —
`areaServed: Poland` to za szeroko. Frazy, na które realnie można wygrać
(„kamerzysta na wesele Warszawa", „filmowanie dronem Mazowsze"), są lokalne.
Rekomendacje:

- dodać miasto bazowe do: tytułu strony głównej, meta description, treści sekcji
  kontakt („Baza w …, działam w całej Polsce"), JSON-LD (`address.addressLocality`,
  `areaServed` z konkretnymi regionami),
- założyć/podpiąć **Profil Firmy w Google** (Google Business Profile) i podlinkować
  stronę — dla lokalnych usług to silniejszy sygnał niż niejedna optymalizacja on-site,
- spójny NAP (nazwa-adres-telefon) na stronie i w profilach social.

### 4.3. Architektura: jedna strona vs. frazy usługowe 🟠 (długoterminowo)

Trzy usługi (film okolicznościowy / montaż / promo) konkurują na jednym URL-u `/oferta`.
Google preferuje dedykowane strony pod odrębne intencje. Docelowa struktura:

```
/oferta/film-slubny      ← „kamerzysta na wesele", „film ślubny [miasto]"
/oferta/montaz-wideo     ← „montaż filmów", „montażysta wideo"
/oferta/wideo-promocyjne ← „film promocyjny dla firmy"
```

Treść już istnieje w `site-content.ts` (lead, bullets, opisy, FAQ per temat) — strony
mogą być generowane z tych danych. To największa pojedyncza inwestycja SEO (1–2 dni),
ale i największy potencjał wzrostu.

### 4.4. Treść wideo niewidoczna dla wyszukiwarek 🟡

Filmy (własne `.webm` i YouTube) nie mają transkrypcji ani opisów na stronie. Szybkie
poprawki: akapit opisu pod każdym filmem promo (teraz jest tylko tytuł), `VideoObject`
JSON-LD, opisy/rozdziały po stronie YouTube (kanał linkuje do strony = dodatkowy sygnał).

### 4.5. Mocna strona: treść FAQ ✅

9 rozbudowanych, naturalnie napisanych odpowiedzi (sprzęt, proces, ceny, prawa do
materiału) to gotowy long-tail content i materiał E-E-A-T. Wymaga jedynie oznaczenia
`FAQPage` (§7.4), by mógł pojawić się w rozszerzonych wynikach.

## 5. Struktura i indeksacja

### 5.1. Linkowanie wewnętrzne 🟡

- Nawigacja desktop pokazuje 3 z 9 pozycji (`DESKTOP_NAV_ITEMS`) — crawler i tak widzi
  sekcje (jedna strona), ale linki do `/oferta` i `/contact` są tylko w nav + stopce
  CTA sekcji. Warto dodać kontekstowe linki w treści (np. z opisów usług na `/` do
  `/oferta`, docelowo do podstron usług).
- Stopka nie linkuje do `/oferta` ani `/contact` — najprostsze miejsce na stałe
  linkowanie wewnętrzne.
- Linki hashowe (`/#about` itd.) nie tworzą osobnych dokumentów — OK, ale canonical
  (§3.2) zabezpieczy warianty z hashem/parametrami.

### 5.2. Rozjazd `/contact` ↔ „O mnie" 🟠

Trasa `/contact` renderuje treść „O mnie" (bio, dlaczego to robię, wideo) z tytułem
„O mnie". Z perspektywy SEO to dwa różne tematy (intencja „kontakt" vs. „kim jest
autor") sklejone pod mylącym URL-em. Opcje:

- **minimum**: tytuł/description odzwierciedlające całość („O mnie i kontakt"),
- **docelowo**: rozdzielić na `/o-mnie` (bio, wideo, E-E-A-T) i `/kontakt` (dane,
  formularz) — `site-content.ts` już ma osobną gałąź `aboutMe`, a przy zmianie URL-i
  ustawić przekierowania 301 w `next.config.mjs`.

### 5.3. Wydajność jako czynnik rankingowy 🟠

Dwa elementy audytu 008 wprost dotykają Core Web Vitals (składnik rankingu):

- **Preloader wymusza ≥ 1,1 s** widoczności przy pierwszej wizycie (`MIN_VISIBLE_MS`) —
  to bezpośrednia kara dla LCP na pomiarach polowych (CrUX liczy pierwsze wizyty).
  Rozważyć skrócenie do ~600 ms lub pokazywanie preloadera tylko, gdy zasoby realnie
  się ładują.
- **Podwójne pobieranie obrazu hero** (surowy PNG w preloaderze + zoptymalizowany
  w `next/image`) — wydłuża LCP na wolnych łączach.

Po wdrożeniu poprawek zmierzyć: Lighthouse (lab) + PageSpeed Insights (dane polowe,
gdy domena zbierze ruch).

## 7. Gotowe poprawki (do wdrożenia)

### 7.1. `app/sitemap.ts`

```ts
import type { MetadataRoute } from 'next'

const siteUrl = process.env.SITE_URL ?? 'https://example.com'

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    { url: siteUrl, lastModified: new Date(), changeFrequency: 'monthly', priority: 1 },
    { url: `${siteUrl}/oferta`, lastModified: new Date(), changeFrequency: 'monthly', priority: 0.8 },
    { url: `${siteUrl}/contact`, lastModified: new Date(), changeFrequency: 'yearly', priority: 0.5 },
  ]
}
```

### 7.2. `app/robots.ts`

```ts
import type { MetadataRoute } from 'next'

const siteUrl = process.env.SITE_URL ?? 'https://example.com'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: { userAgent: '*', allow: '/' },
    sitemap: `${siteUrl}/sitemap.xml`,
  }
}
```

### 7.3. Canonical — w `metadata` layoutu i per trasa

```ts
// app/layout.tsx — w obiekcie metadata:
alternates: { canonical: './' },
// dzięki metadataBase Next zbuduje pełny absolutny URL per trasa
```

### 7.4. `FAQPage` JSON-LD (generowany z `site-content.ts`)

```tsx
// np. w components/sections/Faq.tsx albo w app/page.tsx (server-side)
const faqJsonLd = {
  '@context': 'https://schema.org',
  '@type': 'FAQPage',
  mainEntity: siteContent.faq.items.map((item) => ({
    '@type': 'Question',
    name: item.question,
    acceptedAnswer: { '@type': 'Answer', text: item.answer },
  })),
}
// render: <script type="application/ld+json"
//   dangerouslySetInnerHTML={{ __html: JSON.stringify(faqJsonLd).replace(/<\//g, '<\\/') }} />
```

Uwaga: FAQ jest w komponencie klienckim — skrypt JSON-LD najlepiej dodać w `app/page.tsx`
(server component), by trafił do statycznego HTML-a.

### 7.5. Rozszerzony `ProfessionalService` (w `app/layout.tsx`)

```ts
const jsonLd = {
  '@context': 'https://schema.org',
  '@type': 'ProfessionalService',
  name: authorName,
  url: siteUrl,
  image: `${siteUrl}/opengraph-image.jpg`,
  description: siteContent.structuredDataDescription,
  serviceType: ['Fotografia', 'Film', 'Drony'],
  telephone: process.env.NEXT_PUBLIC_ABOUTME_PHONE,   // po uzupełnieniu env
  email: process.env.NEXT_PUBLIC_ABOUTME_EMAIL,
  address: { '@type': 'PostalAddress', addressLocality: 'MIASTO', addressCountry: 'PL' },
  areaServed: { '@type': 'Country', name: 'Poland' },
  sameAs: siteContent.hero.social.map((s) => s.href),
}
```

### 7.6. Walidacja env przy buildzie (`next.config.mjs`)

```js
const required = ['SITE_URL', 'AUTHOR_NAME']
if (process.env.NODE_ENV === 'production' && process.env.VERCEL) {
  const missing = required.filter((name) => !process.env[name])
  if (missing.length) {
    throw new Error(`Brak wymaganych zmiennych środowiskowych: ${missing.join(', ')}`)
  }
}
```

(Analogicznie warto potraktować `NEXT_PUBLIC_*` dla telefonu/e-maila — patrz audyt 008, F-02.)
